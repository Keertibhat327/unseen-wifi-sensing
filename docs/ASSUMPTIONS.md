# Assumptions and evidence

**M5 update (2026-10-10):** durable mock/Telegram alert code, external worker, API guards, allowlisted packaging, dashboard build and deployment instructions are implemented. Local tests pass; hosted services are not configured. Postgres integration is in CI but was skipped locally because Docker's engine is unavailable. No real Telegram message was sent. [M5 guide](M5_DEPLOYMENT.md) supersedes historical statements below about absent Telegram support and untested local packaging.

**M4 update (2026-10-10):** offline privacy/robustness experiments, optional statistical anomaly monitoring and a default-off local identity CLI are now implemented. No real person was enrolled. Statistical anomalies do not imply intent; reduced CSI features do not guarantee privacy. [M4 evidence and limits](M4_RESEARCH.md) supersede historical statements below about absent identity functionality. Hardware and deployment remain unvalidated.

Original M1 evidence checked 2026-10-09. No hardware was available. **M2/M3 update (2026-10-10):** calibrated amplitude heuristics replace the M1 label-driven detector described below. Fall confirmation/cancellation, occupancy states and room schedules are implemented and synthetic-tested. M3 adds real trained models, both dataset audits, gap-aware resampling and grouped evaluation; learned scores remain advisory. There is still no validated headcount, geometric localization or working serial parser. [M2 details](M2_DETECTION.md) and [M3 audit and limitations](M3_ML.md) supersede the historical implementation-status notes below, including the prospective M3 work.

1. **WiFall was inspected, not inferred.** Downloaded the 29.4 MB archive from [RS2002/WiFall](https://huggingface.co/datasets/RS2002/WiFall/tree/main), opened its CSV header and rows, and ran the adapter on the first recording. Observed paths are `WiFall/ID0/fall/<timestamp>_104_1.csv`, not just `<person>/<action>.csv`. Action folders also include mixed casing (e.g. `Jump`). M3 must derive labels and recording IDs from verified paths, preserving each recording as one split group.
2. Observed columns include `type`, `seq`, `timestamp`, misspelled `taget_seq`/`taget`, radio metadata, `len`, `first_word_invalid`, `data`. The first inspected row has `len=104` and a JSON signed-byte array. Counts live only in the dataset config. A smoke test compares decoded magnitudes with the actual archive.
3. The [dataset card](https://huggingface.co/datasets/RS2002/WiFall/blob/main/README.md) says timestamps use UTC+8 and complex pairs are real then imaginary. It also says its description was generated by Grok3. Treat prose claims (recording duration, nominal rate, already-selected subcarriers) as provisional. Amplitude is unaffected by swapping pair order; phase is not. Verify phase ordering against collector code before phase research. Config records this assumption explicitly.
4. `configs/wifall.json` uses the card's nominal rate. It is **not** a claim that packets are uniformly sampled. The adapter reads timestamps without resampling; M3 must measure cadence, identify gaps and resample explicitly before making fixed-rate model windows.
5. [Espressif's ESP32-S3 CSI documentation](https://docs.espressif.com/projects/esp-idf/en/v5.0.4/esp32s3/api-guides/wifi.html#wi-fi-channel-state-information) describes imaginary/real bytes, multiple possible LTF sections and potentially invalid initial bytes. Thus no WiFall layout is assumed to be an ESP serial layout. Firmware-version-specific parsing remains TODO until real samples exist.
6. When configured to drop the invalid prefix, the decoder drops that prefix on **all** frames so columns keep the same physical meaning. Selection indices apply after configured section concatenation and prefix removal. Never switch removal behavior between training and inference. Fixed section layouts reject undersized packets; a future ESP adapter must reject or explicitly route unknown packet layouts.
7. The synthetic config deliberately uses a different rate and carrier count from WiFall. M1's motion score and occupancy threshold are demonstrations only. Fall and zone events are labelled injected scenarios; there is no fall confirmation or calibrated headcount. Silence can mean a still person, not an empty room.
8. Local gateway timestamps rely on the host clock. UTC conversion does not fix a bad clock. Replays preserve historical source times. No wall-clock synchronization or future-skew policy is implemented yet.
9. One gateway/device per room remains the M2 room-state assumption. Multi-receiver fusion is not implemented; the API selects the latest occupancy/presence report per room. M2 does not infer a numeric headcount or geometric sub-room location.
10. Dataset licensing was not established from the downloaded card (no license field). No original recordings or upstream source code are committed. Resolve reuse/redistribution terms before publishing datasets or trained derivatives. Cite the dataset and [KNN-MMD paper](https://arxiv.org/abs/2412.04783) in M3. No upstream algorithm code was copied.
11. Identity functionality is absent, not merely hidden. M4 requires opt-in consent, local-only storage and deletion. No firmware, traffic capture, interference or jamming code is included.
12. Vercel/Netlify files are scaffolds, not evidence of a successful deployment. SQLite tests pass locally; hosted Postgres and serverless behavior need M5 validation. Telegram is not implemented in M1.
